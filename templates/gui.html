How Periods Are Validated

Each period (tWCK for LP5, tCK for LP4) is validated against the JEDEC memcfg table boundaries. For LP5, the valid range changes per period depending on which features are active at that frequency:

  • WCK 1:4 is enabled when wck-1to4-upto ≥ period, setting data_freq_ratio = 4 (otherwise 2)
  • Read LECC is enabled when read-lecc-upto > period (strict >), selecting a different memcfg table
  • The internal tCK seen by the memcfg lookup is period × data_freq_ratio
  • For LP4, period bounds are fixed at 468 – 5000 ps

Understanding "upto" and "from" Fields

Most timing threshold fields use upto semantics: the feature is enabled when the current period ≤ the upto value (i.e., at frequencies higher than 1/upto). A larger upto value enables the feature across more (slower) frequencies.

WCK Always-On uses a window: enabled when from ≤ period ≤ upto. Setting from > upto disables it entirely.
