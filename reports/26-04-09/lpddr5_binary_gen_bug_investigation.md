# LP5 Binary Generation Bug Investigation Report - 2026-04-09

## Summary

Investigated LP5 timing entry parsing issue where only 1 entry is detected instead of 4. Concluded the issue is in **binary generation**, not parsing.

## Investigation Findings

### 1. Confirmed: gui.py t_ck Range Filter is CORRECT

The filter `100 < t_ck < 10000` in `gui.py:101-102` correctly filters garbage entries:
- Entry 0: t_ck=1256 → **valid** (in range)
- Entry 1: t_ck=0 → **filtered** (out of range)
- Entry 2: t_ck=1179666 → **filtered** (out of range)
- Entry 3: t_ck=11206782 → **filtered** (out of range)

### 2. Confirmed: LP5 WCK 4:1 Conversion is CORRECT

Input periods [314, 418, 556, 2500] with wck-1to4 mode:
- Entry 0: 314 × 4 = 1256 ✓
- Entry 1: 418 × 4 = 1672 ✓
- Entry 2: 556 × 4 = 2224 ✓
- Entry 3: 2500 × 2 = 5000 ✓

All converted values are in range 100-10000.

### 3. Root Cause: Binary Generation Bug

**orbit_timing_params.c (generated by Python) - CORRECT:**
```
Entry 0: {796,1256,...}
Entry 1: {598,1672,...}
Entry 2: {449,2224,...}
Entry 3: {200,5000,...}
```

**Binary (ddr_timing_table.bin) - CORRUPTED:**
```
Entry 0: freq=796, t_ck=1256
Entry 1: freq=0, t_ck=0
Entry 2: freq=0, t_ck=1179666
Entry 3: freq=8257631, t_ck=11206782
```

### 4. Bug Location

`gen_timing_params` - function `gen_timingtable_bin()` (lines 812-856):

```python
def gen_timingtable_bin(my_values):
    type_format_list = get_type_format_list()
    byte_str = b''
    value_list = []      # Accumulates ALL entries
    format_list = ""      # Accumulates ALL entries
    
    for c_values in my_values:
        # Parse and append to value_list
        ...
        value_list.append(c_value)
        format_list += type_format
    
    # Pack ALL entries at once (BUG)
    byte_str += struct.pack(format_list, *value_list)
```

The function accumulates ALL entries into one list and packs them together, causing field misalignment.
