# Detailed Plan: Binary Layout Fix - Remaining Work

## Issue Summary

The binary generation (`ddr_config_init.py`) does NOT properly use ctypes struct layout. The generated binary has values at OLD offsets (0xEC, 0xF0, etc.) instead of NEW ctypes struct offsets (0xE3, 0xEB, etc.). This causes garbage values at the new offsets that gui.py now reads from.

---

## Root Cause Analysis

### Problem
1. **orbit_config.py** defines ctypes struct with specific field offsets
2. **gui.py** was hardcoded to read from OLD offsets (0xEC, 0xF4, etc.) 
3. **ddr_config_init.py** generates binary using ctypes struct BUT the struct layout appears DIFFERENT from what we calculated
4. After updating gui.py to use NEW ctypes offsets, the values are wrong because the binary doesn't have correct ctypes layout

### Evidence
- Binary has 48000 at offset 0xEC (OLD gui.py offset for temp)
- ctypes struct should have zq_calibration_period at 0xE3, but value is 0
- The values are at DIFFERENT places than expected

### How C Binary Generation Works (gen_ddr_config)

1. **gen_ddr_config** runs gcc on ddr_config_bin.c
2. ddr_config_bin.c includes "ddr_config.h" (line 11)
3. gcc compiles with preprocessor flags:
   ```bash
   gcc -D DDR_TYPE=5 -D DDR_TWO_CHANNEL=0 -D ORBIT_DENSITY=4 ...
   ```
4. **The broken ddr_config.h IS used and causes compilation to FAIL!**
