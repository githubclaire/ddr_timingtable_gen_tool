### Phase 3: Full Field Comparison

**Comparison Source**: Reference binaries (*.ref.bin), NOT timing_params.c

**Reason**: timing_params.c is not a complete binary and cannot be parsed for timing entry values

**Fields to Compare**:

| Field | Count | Offset Range | Description |
|-------|-------|--------------|-------------|
| freq | 1 | 0x00 | Frequency in MHz |
| t_ck | 1 | 0x04 | Timing period in ps |
| timing_zqcal | 1 | 0x08 | ZQ calibration timing |
| timing_param | 21 | 0x0C-0x5C | Main timing parameters |
| timing_derate | 2 | 0x60-0x68 | Timing derate values |
| dfi_timing_param | 8 | 0x68-0x84 | DFI timing parameters |
| rl | 1 | 0x110 | Read latency |
| wl | 1 | 0x111 | Write latency |
| mr_rl | 1 | 0x112 | MR read latency |
| mr_wl | 1 | 0x113 | MR write latency |
| read_link_parity | 1 | 0x11F | Read link parity |
| write_link_parity | 1 | 0x120 | Write link parity |

**Validation Logic**:
```python
# For each entry in reference binary:
expected = extract_from_reference_binary(entry_idx, field_name)
actual = parsed_entries[entry_idx][field_name]

if expected != actual:
    report_mismatch(entry_idx, field_name, expected, actual)
```

### Phase 4: Fix gui.py Entry Validity Filter

**Problem**: Enable flag logic passes for garbage data (t_ck=2031647, 3276850, etc.)

**Solution**: Add t_ck validity check in parse_timing_entries():

```python
# After reading t_ck (around line 102 in gui.py)
t_ck = struct.unpack('<I', data[entry_offset+0x04:entry_offset+0x08])[0]

# Filter: valid entries must have t_ck in reasonable range (100-10000 ps)
if not (100 < t_ck < 10000):
    continue
```
